# Stage 01 — Product definition

## 목표

제품의 **한 줄·범위·WOW·유려 규칙**을 잠근다.  
이 문서가 OK이면 구현/스키마는 이 범위를 벗어나지 않는다.

## 제품 한 줄

**가제: Next3**  
안내문·공지·서류 이미지(또는 텍스트)를 넣으면, AI가 **지금 사용자가 할 일만 최대 3개**로 남긴다.

영문 태그라인(제출/랜딩용 초안):  
*Don’t read it. Do the next three.*

## 누가 / 언제

- **누가:** 학교 가정통신문, 병원·관공서 안내, 임대·관리비 고지, 회사 내부 공지를 “읽고도 뭐 할지 모를 때”의 사람
- **언제:** 사진 찍거나 PDF/캡처를 받은 **직후 30초**

## 병목 (발표 ①②)

- 긴 공지 → “이해한 척” → 마감·제출·준비물을 놓침
- 병목은 **문해력이 아니라 행동 추출**

## 해결 WOW (발표 ③)

- 입력: 지저분한 긴 서류/사진
- 출력: **요약 문단 거의 없음**. 할 일 카드 ≤3 + **언제(due)** + **안 하면 생기는 일**
- 각 할 일에 **원문 근거 한 줄**이 붙어 “AI가 지어내지 않았다”가 보임

## In scope (MVP)

1. 이미지 업로드 및/또는 텍스트 붙여넣기
2. AI 분석 → 구조화 결과
3. 결과 화면: 할 일 ≤3, 각각 `title`, `due` (있으면), `if_skipped` (안 하면 생기는 일), `evidence`, `confidence`
4. `confidence`가 낮거나 근거 없으면 **확인 필요**로 표시 (거짓 확정 금지)
5. **언제 최소치:** 서류에 기한이 있으면 `due` 표시 / 없으면 “기한 없음” 또는 확인 필요 (푸시 알람 없음)
6. **미룬이 각성 최소치:** 카드당 `if_skipped` 한 줄 (알림 앱이 아니라 결과 화면의 문장)
7. **캘린더 연결 최소치:** due가 있는 할 일 → `.ics` 다운로드 (서버 푸시·자동 등록 없음)
8. 모바일 웹 단일 플로우 (카메라 롤 업로드 포함)
9. 샘플 데모용 고정 예시 1~2개 (심사 시 API 불안 대비)

## Out of scope (MVP에서 명시적 제외)

- 관공서·학교 사이트 대신 신청/결제
- 계정·소셜 로그인·클라우드 동기화
- **푸시 알림·반복 알람·미루기 습관 코치** (우승 후)
- 캘린더 앱 자동 쓰기 (`.ics` 수동 다운로드만)
- 다국어 본격 지원 (UI 한국어 우선)
- 네이티브 iOS 앱스토어 제출
- 채팅형 만능 비서 UI

## 유려함 규칙 (아이폰 초기 감성 + 아주 조금 앞선)

1. **한 자리 일:** 첫 화면 할 일은 “넣기”와 “결과”뿐
2. **비우기:** 긴 요약·팁·배지 나열 금지. 여백이 기능
3. **최대 3:** 4번째 할 일은 만들지 않음. 중요도 순으로 자름
4. **근거 없는 할 일 금지:** evidence 없으면 카드 생성 안 함
5. **모름을 아름답게:** “이 서류에서 기한을 찾지 못함”이 버그가 아니라 정직한 UX
6. **Her의 한 장면:** 떠드는 대화창이 아니라, **건네면 고요히 할 일만 남는** 감각
7. **시각:** 과한 그라데이션·카드 덩어리·대시보드 금지. 타이포·여백·한 장의 결과

## AI 역할 (한 줄)

문서에서 **실행 가능한 다음 행동**을 추출하고 순위화한다.  
설명·잡담·일반 지식 보충은 하지 않는다. (Stage 02 스키마로 강제)

## 성공 정의 (해커톤)

- 심사/투표자가 30초 데모로 WOW를 이해
- 샘플 서류 2종에서 할 일이 “그럴듯 + 근거 있음”
- 링크가 평가 기간 동안 살아 있음
- 제출문에 문제 / AI 활용 / 스택이 한 페이지로 설명 가능

## 리스크와 대응

| 리스크 | 대응 |
|--------|------|
| OCR·비전 오인식 | evidence 필수 + 확인 필요 플래그 |
| 할루시네이션 할 일 | 스키마 검증, 원문 미포함 시 drop |
| “그냥 요약기” 공격 | UI에서 요약 제거, 발표 훅으로 방어 |
| “또 할 일 앱” 공격 | 알람 없음·추출이 본체임을 데모/카피로 고정 |
| API 비용/키 | Stage 04에서 키 관리, 데모 캐시 |

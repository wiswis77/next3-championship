iOS / iPhone · 상용 기능 중심

아이폰이 앱에게 열어주는 것들

“무엇이 가능한지”를 기획·제품 관점에서 길게 정리한 가이드입니다. 모든 API를 나열하지 않고, 실제로 자주 제품화되는 능력과 그 능력이 만드는 사용자 경험, 제약까지 묶었습니다. LiDAR처럼 “신기한 한 방”이 아니라, 상용 앱에서 반복적으로 쓰이는 층위를 중심으로 합니다.

1. 이 문서의 목적

아이폰 앱을 잘 만든다는 건 두 층이 겹칩니다. 하나는 SwiftUI·네비게이션·상태관리 같은 앱을 조립하는 정석이고, 다른 하나는 카메라·AR·결제·알림·위젯처럼 기기가 열어주는 능력을 제품 경험으로 바꾸는 일입니다.

이 문서는 후자에 가깝습니다. “RoomPlan이 뭐지?”를 외우는 게 아니라, 저런 게 있으면 어떤 서비스가 성립하는가를 머릿속에 지도를 만드는 용도입니다. 구현 세부·최신 API 시그니처는 그때그때 문서/검색이 더 정확합니다. 여기서는 가능 범위와 상용 패턴을 깊게 가져가면 됩니다.

한 줄 요약: 기능을 “안다”는 것은 API 암기가 아니라, “이 제품은 카메라 권한이 핵심이다 / 이건 Pro + LiDAR가 없으면 약하다 / 이건 위젯으로 재방문시킨다”처럼 기획 가설을 기기 능력에 고정할 수 있다는 뜻입니다.

2. 읽는 법 · 태그 의미

  • 상용 빈도 높음 — 많은 카테고리 앱에서 반복적으로 등장
  • 기기/모델 제약 — Pro, LiDAR, 최신 OS, 특정 칩 등
  • 대표 프레임워크 — 구현 시 찾아볼 이름

아래 각 기능 카드는 “무엇을 할 수 있는가 → 어떤 제품에 자주 쓰이는가 → 기획할 때 조심할 점” 순입니다.

3. 화면 · 시스템 UI

가장 흔한 “아이폰 기능”은 사실 센서가 아니라 시스템과 같은 언어로 말하는 UI입니다. 사용자가 “아이폰 앱답다”고 느끼는 대부분은 여기입니다.

SwiftUI / UIKit 화면 구성

리스트, 폼, 탭, 네비게이션 스택, 시트(모달), 풀스크린 커버, 검색, 스와이프 뒤로가기. 신규 앱은 SwiftUI가 주류이고, 카메라·커스텀 렌더·레거시는 UIKit/Metal과 혼용합니다.

상용 패턴: 온보딩 → 탭바 홈 → 상세 → 설정. 커머스·콘텐츠·유틸리티 거의 전부 이 뼈대입니다.

상용 빈도 높음 SwiftUI · UIKit

시스템 공유 · 문서 열기 · 사진 선택

Share Sheet로 다른 앱에 보내기, Files에서 파일 고르기, Photos 피커로 이미지/영상 선택, Document Scanner로 종이 스캔. “우리 앱 안에 다 구현”보다 OS가 주는 UI를 쓰는 편이 신뢰·심사·개발비용에서 유리한 경우가 많습니다.

상용 빈도 높음 PhotosUI · UniformTypeIdentifiers · VisionKit

다크모드 · Dynamic Type · 접근성

글자 크기 확대, VoiceOver, Reduce Motion. “기능”처럼 안 보이지만 상용 앱·특히 금융/헬스케어/공공성 있는 서비스에서는 사실상 필수에 가깝습니다. 기획 단계에서 폰트·대비·제스처 의존도를 미리 보면 나중에 덜 깨집니다.

상용 빈도 높음 Accessibility · Dynamic Type

홈 화면 위젯 · Lock Screen 위젯

앱을 안 열어도 정보/ Habit / 단축 진입을 보여줍니다. 날씨, 캘린더, 금융 잔고 요약, 습관 스트릭, 배송 상태처럼 재방문 유도가 목적인 제품에서 상용화 빈도가 높습니다. 위젯은 상호작용이 제한적이고 갱신 주기에 제약이 있어 “작은 대시보드”로 설계해야 합니다.

상용 빈도 높음 WidgetKit

Live Activities · Dynamic Island

배달 현황, 스포츠 스코어, 타이머, 탑승 게이트, 운동 세션처럼 지금 진행 중인 일을 잠금화면·다이나믹 아일랜드에 붙입니다. 알림보다 “계속 눈에 띄는 상태”가 필요할 때 강력한 차별점입니다. 시작/종료 조건·배터리·남용 시 사용자 피로를 기획에 넣어야 합니다.

상용 빈도 높음 ActivityKit

App Clip

앱 설치 없이 작은 기능만 즉시 실행(QR, NFC, 사파리 배너, 지도 등). 매장 주문, 렌탈 잠금해제, 이벤트 체크인처럼 설치 장벽을 낮추는 순간 경험에 쓰입니다. 용량·API 제한이 있어 “미니 앱”으로 범위를 잘라야 합니다.

App Clips

4. 카메라 · 미디어

스마트폰 앱의 고전적 해자입니다. “촬영 → 편집 → 저장/공유” 파이프라인은 SNS, 커머스(상품 사진), 문서, 인증, QR, 뷰티, 홈 인테리어까지 Broad하게 상용화됩니다.

사진·영상 촬영 / 커스텀 카메라 UI

시스템 카메라 앱을 여는 수준을 넘어, 가이드 오버레이·연속 촬영·해상도·프레임레이트·손떨림 등을 앱이 통제하려면 AVFoundation 기반 커스텀 카메라가 필요합니다. QR 고속 스캔, 측량 가이드, 뷰티 필터 프리뷰 등이 전형적입니다.

상용 빈도 높음 AVFoundation · AVCaptureSession

사진 라이브러리 읽기/쓰기

최근 항목만 접근, 제한된 라이브러리, 저장 위치(앨범) 등 프라이버시 모델이 강화되어 있습니다. “갤러리 전체 훑기”형 기능은 권한 설득 카피가 제품의 일부가 됩니다.

상용 빈도 높음 PhotoKit · PhotosUI

마이크 · 음성 메모 · 통화 품질 오디오

녹음, 음성 메시지, 음악 앱, 회의 노트. 백그라운드 녹음은 정책·심사·고지가 민감합니다. 음성→텍스트는 온디바이스 음성인식 또는 서버 STT와 결합하는 상용 패턴이 많습니다.

상용 빈도 높음 AVAudioSession · Speech

QR / 바코드 / 문서 스캔

결제, 티켓, 재고, 로그인, 포장 추적. Vision/AVFoundation으로 실시간 디코드하거나 VisionKit 문서 스캐너로 “종이 → 깔끔한 이미지/PDF”를 만듭니다. 단순 QR 한 장이면 시스템 수준으로도 충분하고, 고밀도·연속 스트림·특수 코드는 별도 설계가 필요합니다.

상용 빈도 높음 Vision · AVFoundation · VisionKit

5. 인식 · 온디바이스 머신러닝

“AI 앱”이 아니어도, 상용 앱은 이미 많이 기기에 판단을 맡깁니다. 서버로 보내면 지연·비용·프라이버시 이슈가 생기므로 가벼운 인식은 온디바이스가 기본 선택지가 되는 경우가 많습니다.

얼굴·텍스트·사물·포즈 등 비전 태스크

OCR(영수증, 명함), 사람 영역 분리, 문서 감지, 바코드, 이미지 분류. 번역 카메라, 가계부 영수증, 커머스 검색, 운동 자세 코칭 등에 상용화됩니다.

상용 빈도 높음 Vision · VisionKit

Core ML 커스텀 모델

앱 전용 분류기/탐지기/추천 후보 생성. 모델 크기·발열·구형 기기 성능이 제품 범위를 정합니다. “모든 아이폰에서 동일 품질”을 약속하기 어렵다는 점을 기획에 명시하는 게 좋습니다.

Core ML · Create ML

자연어 · 번역 · 받아쓰기

온디바이스 언어 처리, 번역 API, 키보드 받아쓰기 연동. 노트·메신저·학습·여행 앱에서 보조 기능으로 자주 붙습니다.

Natural Language · Translation · Speech

6. AR · 3D · 공간 (LiDAR 포함)

당신이 LiDAR에서 느낀 “신박함”이 여기에 해당합니다. 다만 상용에서는 와우 데모와 반복 사용 유틸리티가 갈립니다. 성공하는 쪽은 대개 “예쁜 3D”보다 측정·배치·스캔·미리보기처럼 효용이 뚜렷한 경우입니다.

ARKit — 세계 추적 · 평면 감지 · 앵커

카메라로 현실을 보고, 그 위에 가상의 점/면/물체를 고정합니다. 가구 배치 미리보기, 교육, 게임, 매장 네비게이션, 포켓몬고류 위치AR의 기반입니다. 조명 추정, 이미지/오브젝트 트래킹, 페이스 트래킹(전면) 등 세부 능력이 많습니다.

상용 빈도 높음 ARKit

RealityKit — 렌더링 · 엔티티 · 인터랙션

AR/3D 장면을 현대적으로 그리는 쪽. 모델 불러오기, 물리, 탭 제스처, USDZ 콘텐츠. “ARKit이 현실 이해, RealityKit이 가상 표현”에 가깝게 이해하면 기획이 쉽습니다.

상용 빈도 높음 RealityKit · USDZ

LiDAR · scene depth

빛이 돌아오는 시간으로 깊이(공간 거리)를 더 안정적으로 얻습니다. 어두운 곳·텍스처 없는 벽에서도 평면/메시가 잘 잡히는 편이라 측정, 오클루전(가상이 현실 소파 뒤에 가림), 룸 스캔 품질이 올라갑니다.

기획 함정: 모든 아이폰에 있지 않습니다. Pro 라인 등 모델 제약이 있어 “전 사용자 필수 경로”로 두면 시장이 줄고, “있으면 더 정확”으로 두면 제품이 건강합니다.

기기/모델 제약 ARKit depth · LiDAR

RoomPlan — 방 스캔 → 구조화 모델

방을 비추며 걸으면 벽·문·창·가구 대략을 구조화된 데이터/3D로 줍니다. 인테리어, 이사, 부동산, 리모델링 견적, 스마트홈 배치 같은 “공간을 데이터로 만드는” 상용 시나리오에 직접적입니다. 캡처는 실기기 iOS 앱이 필요하고, 결과물을 웹/에디터로 넘기는 파이프라인이 제품의 절반입니다.

기기/모델 제약 RoomPlan

Object Capture / 포토그램메트리

물건을 여러 각도 사진으로 찍어 3D 모델화. 커머스 상품 뷰어, 아카이빙, 제작 파이프라인. 촬영 품질·조명·후처리가 서비스 품질을 좌우합니다. “버튼 하나면 박물관급”은 보통 아닙니다.

Object Capture · RealityKit

측정 (Measure류)

길이·면적 측정. DIY, 물류, 인테리어 견적 보조. LiDAR가 있으면 체감 정확도·안정성이 좋아지는 편이나 법적/공사 수준의 정밀도를 약속하면 위험합니다. UX 카피에 “대략/참고용”이 중요한 카테고리입니다.

ARKit
상용 AR의 현실: 데모는 쉽고 리텐션은 어렵습니다. 조도, 넓은 유리, 흰 벽, 사용자 촬영 스킬, 모델 용량, 열/배터리가 품질을 흔듭니다. “AR이 메인”보다 “업무를 끝내는 수단으로 AR 한 방”이 상용에서 더 자주 이깁니다.

7. 위치 · 지도 · 이동

위치 권한 · 백그라운드 위치

지도, 러닝, 배달, 동네 기반 발견, 분실 방지, 지오펜스(특정 구역 출입 알림). “앱 사용 중”과 “항상” 권한의 심리적·심사적 허들이 전혀 다릅니다. 항상 위치가 필요하면 가치 제안이 매우 선명해야 합니다.

상용 빈도 높음 Core Location

MapKit · 경로 · 검색

지도 표시, 어노테이션, 경로, 로컬 검색. 네이버/카카오/구글 SDK를 쓰는 국내 상용도 많지만, 시스템 MapKit만으로도 충분한 유틸·내부 툴이 많습니다.

상용 빈도 높음 MapKit

지오펜싱 · 비콘성 근접

매장 도착 쿠폰, 자동 체크인, 구역 진입 시 로그. 배터리와 false positive를 어떻게 줄일지가 제품입니다.

Core Location · (Bluetooth)

8. 센서 · 모션 · 근접

가속도·자이로·자세 (Core Motion)

걸음, 흔들기 제스처, 게임 조작, 운동 트래킹 보조, 화면 방향 보정. Health/피트니스·게임·측량 보정에 자주 붙습니다.

상용 빈도 높음 Core Motion

근접 센서 · 조도 · 배터리/열 (간접)

통화 시 화면 끄기 같은 시스템 동작에 가깝고, 앱이 직접 “제품 기능”으로 쓰기보다 촬영/AR 품질(조도)이나 성능 저하 대응 같은 운영 이슈로 만나는 경우가 많습니다.

햅틱 (Taptic Engine)

성공/실패/선택 변경의 촉각 피드백. 결제 완료, 스냅 정렬, 게임 타격감. 작지만 상용 앱의 “손맛”을 좌우합니다.

상용 빈도 높음 UIFeedbackGenerator · Core Haptics

9. 건강 · 운동 · 헬스케어

HealthKit 연동

걸음, 심박수, 수면, 운동 기록 읽기/쓰기. 피트니스·다이어트·의료 인접·보험 웰니스 앱의 허브입니다. 데이터 권한이 세분되어 있고, 의료기기급 주장은 규제·심사 리스크가 큽니다. “건강 참고용”과 “진단”을 기획 언어에서 분리해야 합니다.

상용 빈도 높음 HealthKit

운동 세션 · AirPods/워치 연계 감각

아이폰 단독보다 Apple Watch·이어폰과 묶일 때 데이터가 풍부해집니다. 아이폰만의 제품으로 시작해도, 로드맵에 워치를 둘지 mid-term에 결정하는 편이 좋습니다.

HealthKit · Workout · WatchConnectivity

10. 인증 · 보안 · 결제

Face ID / Touch ID / 기기 암호

앱 잠금, 이체 확인, 민감 노트. 로컬 인증은 “우리 서버 로그인”과 별층입니다. 금융·업무·헬스·다이어리류에서 거의 표준 옵션입니다.

11. 알림 · 실시간 상태

로컬 알림 · 푸시 알림

리마인더, 채팅, 마케팅, 트랜잭션(배송/결제). 권한 요청 타이밍이 전환율을 좌우합니다. “첫 실행 즉시 요청”은 상용에서 점점 비추천 쪽으로 갑니다. 가치를 보여준 뒤 요청이 정석에 가깝습니다.

상용 빈도 높음 UserNotifications · APNs

알림 액션 · 그룹핑 · 타임 Sensible한 중단

알림에서 바로 답장/완료, 스레드 묶기, 집중 모드와의 공존. “울리기만 하는 앱”과 “운영 가능한 알림 시스템”은 다릅니다.

14. 백그라운드 실행

사용자 기대(“뒤에서 계속 돌겠지?”)와 OS 현실(배터리 때문에 많이 죽임) 사이 간극이 큽니다. 상용 앱은 백그라운드 모드를 꼭 필요한 유형만 켜고, 그 밖의 일은 푸시·BGTask·사일런트 푸시·다음 포그라운드 동기화로 설계합니다.

16. 확장 기능 (App Extensions)

본편 앱 옆에 붙어 시스템 곳곳에 스며드는 조각들입니다. 상용에서 “플랫폼 점유”에 중요합니다.

  • Share Extension — 사파리/사진에서 “이 앱으로 보내기”
  • Safari Extension — 콘텐츠 차단, 페이지 도구 (정책 민감)
  • Notification Service Extension — 푸시 수신화·복호화
  • Keyboard Extension — 커스텀 키보드 (권한·신뢰 허들 큼)
  • Widget / Live Activity / App Clip — 앞에서 다룸

확장마다 메모리·API 제한이 큽니다. “본편과 같은 앱”으로 생각하면 일정 사고가 납니다.

17. 권한 · 프라이버시 · 심사 · 한계

아이폰의 진짜 특징은 “많은 센서”보다 센서를 쉽게 안 줌에 가깝습니다. 상용 기획은 기능 목록과 동시에 권한 스토리보드가 필요합니다.

자주 막히는 권한

  • 카메라 / 마이크 / 사진
  • 위치 (특히 Always)
  • 알림
  • 트래킹(ATT) — 광고·크로스앱 추적
  • 연락처 / 캘린더 / 블루투스 / 헬스

상용 기획 체크

권한이 가치보다 크면 제품이 죽음

“가입 전에 위치+사진+연락처”는 이탈률이 폭발합니다. 기능을 만지는 순간에 최소 권한만 요청하는 흐름이 정석에 가깝습니다.

App Store 심사 언어

계정 삭제, 구독 설명, 아동/건강/금융 주장, 웹뷰 껍데기, 미완성 앱, 개인정보 라벨(영양 성분표). “기술적으로 됨”과 “스토어에 나감”은 다릅니다.

시뮬레이터의 거짓말

LiDAR, 진짜 카메라 성능, 푸시, 백그라운드, 결제, Face ID 등은 실기기 없이 “상용 품질”을 확정하기 어렵습니다. AR/RoomPlan류는 특히 그렇습니다.

19. 기획할 때 쓰는 체크 맵

  2. 필수 기기 능력은? (카메라만? LiDAR? BLE 하드웨어? Watch?)
  3. 권한이 몇 개고, 언제 묻나?
  4. 오프라인에서도 가치가 남나?
  5. 재방문 장치는? (위젯, 라이브 액티비티, 알림, 단축어)
  6. 수익화는 StoreKit인가 실물 결제인가?
  7. 데모 와우 vs 매주 쓰는 효용 중 어디에 베팅하나?
  8. 모델 파편화(Pro only)를 감수할 만큼의 해자인가?
LiDAR가 좋은 이유는 “센서가 멋있어서”가 아니라, 공간을 데이터로 만드는 제품이 가능해지기 때문입니다. 같은 방식으로 위젯은 “작은 UI”가 아니라 재방문 채널이고, Live Activity는 진행형 서비스의 잠금화면 점유입니다. 기능을 이름 그대로가 아니라 제품 레버로 기억하면, 당신이 원했던 “더 좋은 아이템 / 더 좋은 기획”으로 연결됩니다.

이 문서는 학습·기획용 개요입니다. OS 버전·모델별 지원·심사 정책은 바뀝니다. 실제 구현 전 Apple Developer 문서와 대상 기기에서 확인하세요.
